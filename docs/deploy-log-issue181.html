00  全体像

何を、何の上に建てたか

今回組んだのは3つのピース。ブラウザは常にNuxt（フロント）としか話さず、Nuxtの中継役（プロキシ）がバックエンドに転送する。バックエンドはExpressだが、Vercel上では「サーバー」ではなく「呼ばれた時だけ動く関数」として動く。

ブラウザが触れるのはNuxtの1オリジンだけ。Express・Neonは背後に隠れている（CSRF対策を「同一サイト」の前提のまま保てる理由）。

01  実際にやった手順

アカウント作成から本番確認まで

エラー対応の前に、まず素直にやった作業の流れ。02の「つまずいた場所」は、主に手順4・6の途中で起きたこと。

  1. Neonでアカウント作成・プロジェクト作成本番用データベースとして。リージョンはシンガポール（日本から一番近い）を選択
  2. Vercelでアカウント作成GitHub連携でサインアップ。リポジトリへのアクセスを許可
  3. バックエンド用のVercelプロジェクトを作成Root Directoryをbackendに指定。環境変数DATABASE_URL（Neonの接続文字列）・SESSION_SECRET（ランダムな文字列）を設定してデプロイ
  4. デプロイエラーに対応ビルドが通って実際にアクセスできるようになるまで、5回ほど原因を調べては直す、を繰り返した（詳しくは次の章）
  5. フロントエンド用のVercelプロジェクトを作成Root Directoryをfrontendに指定。環境変数BACKEND_ORIGIN（手順3で発行されたバックエンドのURL）を設定してデプロイ
  6. 本番データベースにテーブルを作成npx prisma migrate deployを、Neonの直接接続の接続文字列に対して実行
  7. 実際に本番サイトで動作確認新規登録→ホーム画面表示→別ページへ移動→ページ再読み込み→ログアウト→再ログイン、が全部通ることを確認

02  つまずいた場所

起きたこと・原因・直し方

生成されるはずのPrisma Clientが無いままビルドされる

Build failed
症状
ビルドログにCannot find module '../generated/prisma/enums.js'
原因
Prisma Clientはgit管理外で、毎回のインストール時に作り直す設計。生成コマンドの実行タイミングが保証されていなかった
対処
vercel-buildスクリプトでprisma generateを明示的に実行するようにした

既存の小さな型エラーが、実は本番を止めていた

Build failed
症状
「ローカルのtypecheckだけ通らない軽微なバグ」と思っていたものが、Vercelのビルドも巻き込んで止めていた
原因
Vercelは呼び出し先も含めて全ファイルを型チェックする。1箇所だけ型のキャストが漏れていた
対処
他の場所と同じキャストを1行追加

Vercelが、頼んでもいないExpressの自動変換をしてくる

500 crash
FUNCTION_INVOCATION_FAILED
Invalid export found in module "src/index.js".
The default export must be a function or server.
原因
依存関係にexpressがあると、Vercelは「Express製アプリだ」と判断して、こちらが用意した経路とは別に、もう1つ勝手に関数を組み立てようとする
対処
vercel.jsonに「関数として使うのはこのファイルだけ」と明示して、自動変換を止めた

ビルド手順を指定すると、今度は「公開フォルダが無い」と怒られる

Build failed
Error: No Output Directory named "public" found after the Build completed.
原因
APIしか無いプロジェクトなのに、ビルド手順を指定すると「画面（静的ファイル）を作るはず」という前提でチェックされてしまう
対処
ビルド手順自体を空にした。Prisma Clientの生成は、インストール時に自動で走る仕組み（postinstall）に任せた

新しく作ったデータベースは、当然だけど空っぽ

The table `public.users` does not exist in the current database.
原因
ローカルでは開発中にほぼ習慣でmigrate devを実行するため、テーブルが無い状態を意識する機会が無い。Neonのような新しいデータベースには、この「表の設計図を流し込む」作業を誰も一度もしていなかった
対処
npx prisma migrate deployを本番データベースに向けて実行

操作しているうちに、データベースを2つ作ってしまっていた

実害なし

03  セキュリティの確認

パスワード、大丈夫？という素朴な疑問

「昔AWSで簡単なパスワードのせいで不正アクセスされた」という経験を踏まえて、今回の構成を確認した。

✅ 確認できたこと

  • データベースのパスワードは自分で決めていない。Neonが作成時に自動生成した長いランダム文字列が入っている
  • 接続情報が実際に存在するのは「Vercelの環境変数」と「Neonのダッシュボード」だけ。手元のファイルやこの会話には一度も残していない
  • ターミナルの実行履歴（history・~/.bash_history）にも残っていないことを確認済み

04  次にまた新しいプロジェクトをデプロイするなら

先にやっておくと詰まらない4つ

  • Vercelの「Framework Preset」を最初に確認するExpress・Node.jsなど、自動判定が独自の挙動を持つプリセットになっていないか。APIだけのプロジェクトなら基本は素の設定のままでよい
  • ビルド手順は「無し」から始める画面の出力が無いプロジェクトに独自のビルド手順を足すと、思わぬ前提（公開フォルダ必須など）を呼び込みやすい
  • データベースは「作った直後は空」だと覚えておく本番用のマイグレーション適用を、デプロイ手順のチェックリストに必ず入れる
  • 接続文字列は「どこに存在するか」を都度把握するダッシュボード・環境変数・ターミナル履歴、思ったより色々な場所に残りうる

05  出てきた言葉

用語集

フロントエンド／バックエンド
torebuは実は2つの別プロジェクト。フロントエンド（Nuxt）はボタンや画面などユーザーが見て触るもの全部。バックエンド（Express）は画面を一切持たず、「ログインして」「記録を保存して」と頼まれたらデータ（JSON）を返すだけの係。今回の一連のトラブルは、この「画面を持たない」バックエンド特有の事情が原因だった
サーバーレス関数
常時起動しているサーバーではなく、リクエストが来た瞬間だけ立ち上がって処理し、終わったら消えるプログラム。使った分だけ課金される代わりに、待機コストが（無料枠では）ゼロになる
Framework Preset
Vercelが「これはNext.jsだ」「これはExpressだ」などプロジェクトの種類を自動判定し、それに応じたビルド方法を選ぶ仕組み。判定が外れると、今回のような食い違いが起きる
環境変数
パスワードや接続先など、コードには書きたくない値を、実行環境側に外から渡す仕組み。同じコードでもローカル用・本番用で違う値を渡せる
Prisma Client
「このテーブルにこの値を入れて」というSQL文を手で書く代わりに、prisma.user.findUnique(...)のような読みやすいコードでデータベースを操作できるようにする、自動生成コード。設計図（schema.prisma）からprisma generateコマンドが書き出すもので、Wordファイルから作ったPDFのような「元があればいつでも作り直せる成果物」なのでgitには含めない。新しい環境では毎回この生成コマンドを実行する必要がある
マイグレーション
「usersテーブルにemail列を追加する」のような、データベースの設計変更を記録した手順書。順番に適用していくことで、どの環境のデータベースも同じ形に揃えられる。ローカルでは開発中にほぼ習慣で実行するため意識しないが、Neonのような新しいデータベースには誰かが明示的に一度実行してあげる必要がある
プール接続（PgBouncer）
大量の接続要求を、少数の実接続にまとめて中継する仕組み。サーバーレス関数のように「同時にたくさんのインスタンスが起動しうる」構成では、これが無いとデータベース側の接続上限をすぐ使い切ってしまう
typecheck（型チェック）
コードを実際には動かさず、「この変数は文字列のはず」といった型の矛盾だけを検査する作業。実際に動かして確認するnpm testとは別物のため、「テストは全部通るのにtypecheckだけ失敗する」という、実害が無さそうに見えるズレが起きうる。今回はこれが実はVercelのデプロイ自体もブロックしていて、見た目より重大な問題だった
Neon
Postgresというデータベースソフトの構築・管理を代行してくれる会社のサービス。実体はAWSのデータセンター設備を借りて動いている（Amazon直営ではなく、Amazonの倉庫を借りるテナントのようなイメージ）ため、プロジェクト作成時に「AWS Asia Pacific 1 (Singapore)」のようなAWSのリージョン名から選ぶ画面になる
