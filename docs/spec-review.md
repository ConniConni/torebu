# spec.md 読みメモ（一時ファイル）

`docs/spec.md` を読みながら印を付ける用。**読み終えて学習ログに反映したら削除してよい。**

## 印の意味

| 印   | 状態                                                       |
| ---- | ---------------------------------------------------------- |
| `?`  | 言葉・文の意味がわからない（そもそも読めない）             |
| `??` | 意味はわかるが、なぜそうなのかがわからない                 |
| `!`  | 読めば納得できるが、白紙から自分では書けない・説明できない |

**一番大事なのは `!`。** 読んでいて気持ちよく流れてしまう箇所ほど怪しい。
「明日これをClaudeなしで書けるか？」と自問して、怪しければ `!`。

## ルール

1. **調べない。** 読み終わるまで一切調べない
2. **1箇所に30秒以上悩まない。** 印を付けて先へ進む
3. **迷ったら重い方の印**（`?`か`??`なら`?`、`??`か`!`なら`!`）
4. わかったところは空欄のままでよい。○を付ける必要はない

## 最後に：自己テスト

**spec.md を閉じてから**やる。ここが「読めた」と「身についた」を分ける一番速い確認方法。

1. 流れ①「ログインボタンを押してからホーム画面が出るまで」を、思い出して書き出す
   - エンドポイントへリクエスト
   - ミドルウェアで認可状況を確認
   - ルーティングでログイン処理を開始
   - バリデーションでバックエンドにリクエスト可能な内容であることを確認
   - バックエンドで処理
   - バックエンドがDBと通信
   - 結果をフロントへ返却
   - 受け取った内容をフロントで表示

   - 書けたステップ数： \_\_\_\_ / 11

2. 流れ②「『記録』ボタンを押してセットが1件保存されるまで」を、思い出して書き出す
   - 書けたステップ数： \_\_\_\_ / 9

3. `ref` と `useState` の使い分けを、`pendingExercises` のバグを例に説明できるか
   - できた / できない

> **半分も書けなくて正常。** 読んで分かることと、何も見ずに書けることは別の能力で、
> 身につくのは後者だけ。この数字が今のスタート地点になる。
