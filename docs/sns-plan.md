# X運用計画

公式X（@torebu_app）の運用計画。目的は**サービス（torebu.com）への入り口**を作ること。
フォロワー数は手段で、見たい指標は「登録数」と「グループ作成数」。
経緯：[concept.md](./concept.md)「利用者の広げ方」／[backlog.md](./backlog.md)「ユーザー獲得：前提の見直し」。
投稿素材の作り方は`x-assets/README.md`（リポジトリ管理外）。

> 数値目標はフォロワー0からの一般的な伸び方に基づく**仮置き**。1か月後（2026-11-15）に実績で見直す。

## 前提

- 使い方はクローズドな少人数グループ。刺さる相手は**筋トレ仲間がいる／欲しい人**
- 守る原則：出すのは**サービスについての情報だけ**。ユーザーの記録・登録者数などの全体集計値は出さない
- 運用はユーザー。使える時間は**1日30分**（10分しか取れない日は軽量版：返信5件）
- フォロワー0〜100の間は、自分の投稿より**他人の投稿への返信**のほうが発見されやすい

## 目標

| 期間 | 投稿 | フォロワー | 月間インプレッション | リンククリック | 登録（X経由） |
|---|---|---|---|---|---|
| 1か月目（〜11/15）土台づくり | 週5〜7 | 30〜50 | 3,000〜5,000 | 10〜20 | 3〜5人 |
| 2か月目 型を探す | 週5〜7 | 100 | 1万 | 40 | 10人 |
| 3か月目 伸びた型に寄せる | 週5〜7 | 200〜300 | 3万 | 100 | 25人 |

1か月目は「何が反応を取れるか」を知る期間。未達でも気にせず、型の発見を優先する。

## 戦略（X上のアクションに絞る）

目標は上の表のまま。ここでは「Xの中で何をするか」だけを決める（アプリ側の導線改善は対象外）。

### 1. 誰に届けるか
- **軸は「すでに仲間がいる小さなコミュニティ」**（部活・サークル・ジム仲間・職場の筋トレ友達）。
  トレ部は5人以下のグループで使うため、1人が気に入れば仲間ごと登録される。ここが最も効率がよい
- 次点は「仲間が欲しい人」。ただし返信先の優先順位は下げる

### 2. どう見つけてもらうか（フォロワー0〜100の間）
- **返信が主役**。自分の投稿は「プロフィールを見た人が納得する材料」として置く
- 返信先の探し方：
  - 検索で「筋トレ 仲間」「部活 筋トレ」「ジム 友達」「トレ仲間」などを拾い、仲間とのトレを投稿している人に反応する
  - 同規模（フォロワー数百〜数千）のアカウントを優先する。大きすぎると埋もれ、反応も返ってきにくい
  - 個人開発者向けのタグ（#buildinpublic など）は、②開発の裏側の投稿でのみ使う。筋トレ層とは別の読者なので、使い分ける
- 返信の型：①具体的に褒める／共感する ②一言だけ。**宣伝・URLは入れない**

### 3. 見に来た人を逃さない（プロフィールと固定ポスト）
- プロフィールの一文は「何のアプリか＋誰のためか」が3秒で分かること。**差別化は「応援し合える・クローズドな仲間内」**
  （案：「仲間と筋トレを記録して、応援しあうアプリ。招待した仲間だけに見える」）
- 固定ポストは1日目の投稿。仲間に送る前提の文面にそろえる
- 投稿の締めは、**「仲間に送る」「誰かと一緒に」という行動**に寄せる（登録だけで終わると、グループが作られず価値が出ない）

### 4. やらないこと（時間が限られるため）
- 広告、フォロー返し目的の大量フォロー、相互フォロー集め
- 長文・長いスレッド（1か月目は短い投稿で型を探す）
- 他人の投稿への唐突なURL送付、DMでの営業
- ユーザーの記録・登録者数などの公開（前提の「守る原則」）

### 5. 方針を変える基準
- **1か月目の終わり（11/15）の見直し**：
  - フォロワーが10未満、またはリンククリックが5未満 → 返信先の探し方とプロフィールの一文を変える（投稿の柱ではなく「届け方」を疑う）
  - フォロワーは増えたがクリックが少ない → 固定ポスト・プロフィールの導線を変える
  - クリックはあるが登録が増えない → アプリ側の入口（特設ページ）の見直しをIssue化する
- 柱は、2週間分の反応を見て、上位2つに寄せる

## 日課（30分）

1. 投稿1本（10分）：下の「投稿の柱」から選ぶ
2. 他人への返信10件（15分）
   - 対象：筋トレ記録を投稿している人／ジム仲間・部活系／同規模の個人開発者
   - 宣伝はしない。具体的な一言の感想・応援を書く
3. 自分の投稿への反応に返信（5分）。反応してくれた人には必ず返す

## 投稿の柱

| 柱 | 例 | 頻度 |
|---|---|---|
| ① 機能紹介（スクショ） | 作成済みの素材の使い回し、新機能のリリース | 週1〜2 |
| ② 開発の裏側 | 今日直したこと、設計で迷った点 | 週2 |
| ③ 筋トレ小ネタ | 種目の効く部位、記録を続けるコツ | 週1〜2 |
| ④ 問いかけ | 筋トレ仲間は何人？ など | 週1 |
| ⑤ 仲間と続ける話 | 「一人だと続かない」系の共感 | 週1 |

- 本文にはリンクを貼らない（表示されにくいため）。固定ポストとプロフィールに誘導する
- 画像は縦横比4:5（`x-assets/crop_posts.py`）

## 投稿カレンダー・数値の記録

**公開リポジトリには置かない**。投稿の文面案・日々の数値（フォロワー・登録数など）は`x-assets/sns-log.md`（未追跡）に書く。
振り返りの際に、そこへ追記する。

## 流入計測（2026-10-16時点の調査）

- フロントにアクセス解析は**未導入**（`frontend/`にUTM・解析ツールの利用なし）。
  なのでUTMパラメータを付けても、今は集計する先がない
- 当面の測り方（実装不要）：
  - リンククリック：Xのアナリティクス（各投稿のリンクのクリック数）
  - 登録数：Neonコンソールで`users`の週間増加を数える（手順はメモリの「Neonコンソールで登録人数を確認する手順」）
  - 「X経由かどうか」は、登録直後の新規ユーザーに聞く以外に確実な方法が無い。
    増加数の変化を、Xのクリック数と突き合わせて見る
- 実装する場合の次Issue候補（フォロワーが100を超えるあたりで検討）：
  Vercel Web Analyticsの導入（`utm_source`別の訪問数が見える。ただし登録との紐付けまでは取れない）。
  登録時にutm_sourceをユーザーに保存する案は、プライバシー・スキーマ変更を伴うので別途判断
- プロフィールのリンクを`https://torebu.com/?utm_source=x`に変えるのは、解析導入後でよい
